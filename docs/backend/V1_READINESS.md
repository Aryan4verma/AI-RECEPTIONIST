## FAIL / open findings

- **SEC-F7 raw-model resistance remains a historical FAIL:** qwen adopted an injected intent. New deterministic/effect-boundary tests pass for their corpus; adversarial routing/availability disruption beyond it remains possible. Raw model schema validity is no longer mislabeled resistance. A fresh real-model corpus run was not performed this gate.
- Frontend npm audit retains **two moderate package findings** (react-router + react-router-dom): [untrusted navigation destinations](https://github.com/advisories/GHSA-wrjc-x8rr-h8h6), [SSR error hydration](https://github.com/advisories/GHSA-337j-9hxr-rhxg). Reviewed current routes are fixed internal destinations and the app uses client-only declarative routing, so no affected path was found. This is an exposure assessment, not a clean audit. Upgrade to a patched supported Router version with browser regression before production/adding dynamic destinations or SSR.
- Supabase security advisor reports leaked-password protection disabled. Owner must review/enable available Auth protection before production; no setting/paid-plan change made.
- **High-impact least-privilege finding (SEC-F13):** SELECT through the actual configured backend pool reports runtime role `postgres`, BYPASSRLS and audit UPDATE/DELETE privilege. Thus the restricted service_role grant matrix does **not** prove that this PG connection is restricted. The live verifier now checks the actual session's audit/schema/ownership privileges and correctly fails this gate. Owner-scoped runtime-role/grant design, rollout of its credentials and real-role regression are required; no DDL or credential change is authorized here. Backend RLS bypass may be intentional, but schema ownership and audit mutation privileges are not accepted as production least privilege.
